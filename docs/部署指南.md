# qbot 部署指南（本地 → 云服务器）

你的路线：**前期本地跑，后期迁到稳定的云服务器**，三个服务全上
（面板 + 盯盘推送 + 模拟交易）。本指南分两个阶段，照做即可。

> 核心提醒：模拟交易默认 `--broker paper`，**不碰真钱**。整个部署阶段都别上真钱。

---

# 阶段一：本地部署（现在）

适合先熟悉、白天盯盘。缺点是关机/睡眠就停——这没关系，先跑起来。

## 1. 准备（只做一次）

```bash
# 进项目目录后，装依赖
python -m pip install -r requirements.txt        # Windows
python3 -m pip install -r requirements.txt       # Mac

# 复制配置模板（可选：要通知/接OKX才需要填）
copy .env.example .env        # Windows
cp .env.example .env          # Mac
```
想收微信通知就编辑 `.env` 填 `PUSHPLUS_TOKEN`（见 [新手上手指南](新手上手指南.md) 第 5.5 步）。

## 2. 一键启动三个服务

**Windows**：直接双击 `deploy\start_all.bat`
会弹出三个黑窗口：面板 / 盯盘 / 模拟交易。想改标的或策略，用记事本编辑 `start_all.bat`
顶部的 `set SYMBOLS=...`、`set STRATEGY=...`。

**Mac / Linux**：
```bash
bash deploy/start_all.sh
```
三个服务在后台跑，日志在 `logs/`。想改标的：
```bash
SYMBOLS="BTC/USDT ETH/USDT" STRATEGY=supertrend bash deploy/start_all.sh
```

## 3. 使用与查看

- 浏览器打开 **http://127.0.0.1:8000** → 面板（回测 + 实时扫描）
- 看盯盘日志：
  - Windows：看"qbot 盯盘推送"那个窗口
  - Mac/Linux：`tail -f logs/watch.out`
- 信号一变，面板会弹通知/响声；配了微信的话手机也会收到。

## 4. 停止

- Windows：关掉对应黑窗口
- Mac/Linux：`bash deploy/stop_all.sh`

# 阶段二：云服务器部署（后期，实现真正 7×24）

当你决定长期不间断运行时，迁到一台便宜的 Linux 云服务器（阿里云/腾讯云轻量、
或海外 VPS，1核2G 足够，几十块/月）。两种方式，**推荐 A（Docker，最省心）**。

## 方式 A：Docker（推荐，一条命令搞定，环境可复现）

在你自己电脑生成 SSH 后连上服务器，然后：

```bash
# 1. 装 Docker（Ubuntu 示例）
curl -fsSL https://get.docker.com | sh

# 2. 把代码传上去（git clone 或 scp），进入目录
git clone <你的仓库地址> qbot && cd qbot

# 3. 配好密钥
cp .env.example .env && nano .env      # 填 OKX / 通知 的密钥

# 4. 一条命令起全部三个服务（后台+崩溃自动重启）
docker compose up -d --build

# 看日志 / 状态
docker compose logs -f watch
docker compose ps

# 停止 / 更新代码后重启
docker compose down
git pull && docker compose up -d --build
```

## 方式 B：systemd（不想用 Docker）

```bash
# 1. 建用户和目录
sudo useradd -r -m -d /opt/qbot qbot
sudo -u qbot git clone <你的仓库地址> /opt/qbot
cd /opt/qbot

# 2. 建虚拟环境装依赖
sudo -u qbot python3 -m venv .venv
sudo -u qbot .venv/bin/pip install -r requirements.txt

# 3. 配密钥
sudo -u qbot cp .env.example .env && sudo -u qbot nano .env

# 4. 装服务（三个）
sudo cp deploy/systemd/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now qbot-dashboard qbot-watch qbot-live

# 查看状态 / 日志
systemctl status qbot-watch
journalctl -u qbot-watch -f
```
`Restart=always` 保证崩溃自动拉起，`enable` 保证开机自启。

## 面板怎么安全地看（重要）

面板**没有登录验证**，绝不能直接暴露到公网。正确做法是从你自己电脑开 **SSH 隧道**，
把服务器的面板映射到你本地：

```bash
# 在你自己电脑运行（把 user@服务器IP 换成你的）
ssh -L 8000:127.0.0.1:8000 user@服务器IP
```
然后本地浏览器打开 http://127.0.0.1:8000 就是服务器上的面板。关掉 SSH 即断开。
Docker 与 systemd 两种方式都已默认把面板绑在 `127.0.0.1`，配合这条隧道即可。

# 从模拟盘到 OKX 模拟盘/实盘（部署好之后再说）

1. **paper → OKX 模拟盘**：`.env` 填 OKX 模拟盘 key（`OKX_DEMO=1`），
   把 live 服务的 `--broker paper` 改成 `--broker okx`（compose 文件或 systemd 里改），重启。
2. **OKX 模拟盘 → 小额实盘**：先跑稳几周，再把 `.env` 改 `OKX_DEMO=0`，
   命令加 `--i-understand-the-risk`，用**很小**金额验证。切真钱前务必看懂
   `qbot/risk/manager.py` 的每一道风控。

# 常见问题

| 问题 | 解决 |
|---|---|
| 一键脚本双击闪退 | 先按 [新手指南](新手上手指南.md) 确认 `pip install` 成功、`python` 在 PATH |
| 服务器上拉不到行情 | 海外 VPS 连 A股数据源可能慢；OKX 一般通。可换服务器地域 |
| `docker compose` 报没这命令 | 老版本用 `docker-compose`（带横杠）；或重装新版 Docker |
| 面板打不开(服务器) | 确认开了 SSH 隧道；别去公网 IP 直连 |
| 想开机自启(本地Windows) | 把 `start_all.bat` 快捷方式放进"启动"文件夹 |
